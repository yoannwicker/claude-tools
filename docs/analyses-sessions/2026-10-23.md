# Analyse des sessions — 2026-10-23

Période couverte : les 30 derniers jours, du 2026-09-23 au 2026-10-23. Premier rapport :
pas de comparaison possible.

## Méthode

- **Période** : les 30 derniers jours, la fenêtre par défaut de l'API (sans `from=` ni
  `to=`).
- **AgentsView** (`http://127.0.0.1:8080`), API `/api/v1/analytics/` : `summary`,
  `projects`, `tools`, `skills`, `signals`, `signal-sessions?signal=<signal>`, `velocity`,
  `sessions`, `top-sessions`, `activity`, `hour-of-week`. Une fois sans filtre, puis une
  fois par projet suivi (`?project=<nom>`).
- **Projets suivis** : les 4 premiers projets de la période en nombre de messages.
- **Transcripts locaux** (`~/.claude/projects/*/*.jsonl`, dédoublonnés par `uuid` ;
  `~/.claude-profiles/*/projects` n'est qu'un lien vers ce dossier) :
  - projet déduit du `cwd` de la session (les worktrees `.claude/worktrees/` comptent pour
    leur dépôt) ;
  - premier mot de chaque commande Bash, après un éventuel `cd … &&` ;
  - `tool_result` en erreur, classés : refus d'isolation worktree, `git-guard`, refus de
    l'utilisateur (par outil), refus du classifieur du mode auto, projet inconnu du MCP
    IntelliJ, échec d'une commande `gh pr` / `gh api` / `gpr`.
- **Limites** : AgentsView ne note (A à D) qu'une partie des sessions (135 sur 266) ; les
  transcripts ne couvrent que Claude, pas Copilot. L'extrait que `signal-sessions` donne
  pour une session est son premier message, pas l'appel qui a échoué : la cause d'un échec
  se lit dans les transcripts.
- **Commandes `gh`/`gpr`** : seulement quand `gh pr`, `gh api` ou `gpr` est la commande
  appelée (début de commande ou après `;`, `&&`, `|`, `$(`), pas un mot d'un chemin
  (`gpr-record` dans renoshield).

## Recommandations

1. Worktrees : consigne « en session worktree, une commande git par appel, sans
   `cd … &&` » (renoshield, nullaway).
2. IntelliJ MCP : soit un hook `PreToolUse` qui refuse `grep`, `cat` et `find` quand le
   projet est ouvert dans l'IDE, soit assouplir la règle ; ouvrir claude-tools dans l'IDE si
   on garde la règle.
3. Commentaires de revue : les publier par un chemin éprouvé (ligne vérifiée dans le diff,
   revue en attente réutilisée) plutôt que par `gh api` écrit à la main (renoshield).
4. Prompts : pour une tâche non triviale, donner le résultat attendu et comment le vérifier.
5. Une session par story ou PR plutôt qu'une session ouverte plusieurs jours (tous les
   projets).
6. `git-guard` (petsitter_harnessed) : dire dans la consigne du projet ce qui est interdit,
   pour que Claude ne tente pas l'opération.
